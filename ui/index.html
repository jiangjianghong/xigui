编辑规则

id*

规则唯一编号(如 R001)。建议三位数字,留 1000 条扩展空间。退役 ID 不要复用,下游可能还在缓存。

name

中文规则名,用于日志/前端展示。建议带上"什么 × 关系"(如"批复时间×申报时间一致")。

description

规则描述,面向后续维护者的"为什么这么写",仅用于日志/文档,不影响判定。

expected_field_names

预期的两个字段名(用英文逗号分隔),仅文档化、不做强校验,与第一阶段 VLM 抽取的字段名保持一致即可。

require_field_name

是否要求请求里 field_a.name / field_b.name 必填。若 prompt_template 引用了 {a_name}/{b_name},务必勾选 true;否则 LLM 拿到空字符串,判定不准。

system_prompt

LLM 系统提示。建议按本规则的业务领域显式声明(如"你是注册会计师")。留空则不向模型发送 system 消息。

prompt_template*

规则的核心,用自然语言描述判定标准。支持占位符 {a_value} {b_value} {a_name} {b_name}。JSON 示例里的大括号要写双重 {{ }},否则 .format 会报错。
