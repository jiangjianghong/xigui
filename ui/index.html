编辑规则

id*

规则唯一编号(如 R001)。建议三位数字,留 1000 条扩展空间。退役 ID 不要复用,下游可能还在缓存。

name

中文规则名,用于日志/前端展示。建议带上"什么 × 关系"(如"批复时间×申报时间一致")。

description

规则描述,面向后续维护者的"为什么这么写",仅用于日志/文档,不影响判定。

project

所属项目。留空即未分组。改归属也可以在列表里勾选后批量操作。

require_field_name

是否要求请求里每个 field.name 都必填。若 prompt_template 引用了 {键_name},务必勾选 true;否则 LLM 拿到空字符串,判定不准。

system_prompt

LLM 系统提示。建议按本规则的业务领域显式声明(如"你是注册会计师")。留空则不向模型发送 system 消息。

字段定义*

本规则要比对的字段。填字段 ID(如 keyan_name),它就是请求体里的键名;留空则用默认的 field_a/field_b。下方模板区会生成对应 chip,点击即插入占位符。

prompt_template*

规则的核心,用自然语言描述判定标准。占位符与字段 ID 同名:{field_a} {field_b} ... 或自定义的 {keyan_name};加 _name 后缀引用字段名。JSON 示例里的大括号要写双重 {{ }},否则 .format 会报错。

新建项目

key*

项目稳定标识,导出的 yaml 靠它引用项目。只能用字母/数字/下划线,字母或下划线开头。跨环境导入靠它对齐,定了就别轻易改。

name*

项目中文名,项目栏和规则列表里显示的就是它。

description

项目描述,仅文档用。写清这个项目管的是哪一类审核。
